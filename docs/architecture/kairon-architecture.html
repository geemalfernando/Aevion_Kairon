core/
Server · authoritative
re-runs every change; its result wins
  1. validate(): capacity (kg, m³), temperature, outlet access, mall windows, delivery windows, fuel quota, time budgets, two-trip limit, depot, vehicle status
  2. Planner: priority queue, 4 ways to build the plan, independent audit, greedy fallback
  3. Deferrals carry the rule and the calculation; the store sees the reason
  4. Same code in the browser (instant feedback) and on the server (authoritative)
⇅ Offline operation and sync
  1. No signal: deliveries, counts and road reports are saved in the phone's outbox
  2. Signal back: events replay in order; each id is stored once in kairon_events
  3. Stale version: refused (409), the device reloads; nothing is overwritten
  4. Route changed meanwhile: the driver sees what moved and acknowledges it; the dispatcher gets a sync report
🔒 Security
  1. HTTPS at the edge, WAF, no public address for load balancer, tasks or database
  2. scrypt passwords, short sessions with refresh and revocation, rate-limited sign-in
  3. Each role, depot and assignment sees only its own data
  4. Secrets in Secrets Manager; database and proof storage encrypted; least-privilege runtime role
